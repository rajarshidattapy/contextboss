The problem

Agents stuff the prompt and pray.

The window fills, something important gets cut, the model guesses.

✕ silent truncation

The wrong thing gets cut

Naive truncation chops the tail — usually the task itself.

✕ fixed allocation

Rigid budgets waste space

Quiet tiers hoard tokens while retrieval starves.

✕ no audit trail

Nobody knows what went in

When it hallucinates, you can't tell what was dropped.

How it works

The window is a budget. Spend it deliberately.

Hand ContextBoss every candidate block. It decides what goes in, what shrinks, what stays out — and tells you why.

python
from contextboss import ContextManager

mgr = ContextManager("context.db")
mgr.add("Staging deploys freeze on Fridays",
       tags=["deploy"], provenance="slack:#eng")
mgr.add("User is on the Pro plan since Oct 2",
       pinned=True, importance=2.0)

ctx = mgr.assemble("deploy freeze",
    system="You are a careful support engineer.",
    task="Why did the Friday deploy fail?",
    budget=8000)
print(ctx.render())  # never exceeds the window

Install it. Wire it in. Done.

bash
pip install contextboss-core

contextboss                 # live demo: what got in, what got dropped, why
contextboss --budget 400    # squeeze it and watch the tiers fight
python
from contextboss import ContextAssembler, MemoryStore, ToolSpec

asm = ContextAssembler(budget=8000, output_reserve=1000)
asm.system("You are a careful support engineer.")
asm.task("Why are our exports returning 429?")
asm.load_memory(MemoryStore(), query="429 export", k=10)
asm.tool(ToolSpec("get_usage", "Per-minute request counts", {"type": "object"}))

ctx = asm.assemble()
for d in ctx.dropped():
    print(d.item_id, d.reason)   # every decision, explained

The server never reads or modifies the client's conversation history.

One command merges the MCP server and session hooks into ~/.claude/settings.json.

bash
pip install contextboss-mcp
contextboss-mcp install claude-code          # idempotent, preserves existing settings
Your conversation history stays provider-owned: never read into the store, never modified.

Appends the server to ~/.codex/config.toml and a marked block to your project's AGENTS.md.
