The problem

Most agents stuff everything into the prompt and pray.

Then the window fills up, something important gets cut off, and the model starts guessing.

✕ silent truncation

The wrong thing gets cut

Naive truncation chops the tail, which is usually the task or the freshest memory. The model answers a question you didn't ask.

✕ fixed allocation

Rigid budgets waste space

Pre-set splits can't adapt. A quiet tier hoards tokens while the retrieval tier starves, and nobody rebalances.

✕ no audit trail

Nobody knows what went in

When the model hallucinates, you can't tell whether the fact was dropped, compacted, or never made the window at all.

How it works

The window is a budget. Spend it deliberately.

Hand contextboss every candidate block: system prompt, task, memories, retrieved docs, tool schemas. It decides what goes in, what shrinks, and what stays out. And tells you why.

system

Who the model is. Pinned; raises ContextOverflowError if it alone can't fit.

pinned
task

What to do right now. Pinned, truncated only as a last resort.

pinned
memory

Facts about the user and history, ranked by relevance × importance × recency.

flexible pool
retrieval

Docs and chunks, ranked by relevance to the query.

flexible pool
tools

Function schemas, full form, then compact form. Never half a schema.

flexible pool
01

Dynamic budgeting

Output tokens reserved first, then the pool is split by weight with hard caps. Unused share water-fills to tiers that need it.

02

Priority injection

Higher priority goes first within a tier. Output reads system > task > memory > retrieval > tools.

03

Graceful degradation

What doesn't fit gets a second chance compacted, then summarized, and dropped only last. Plug in any LLM summarizer.

04

Spill & verify

Leftover tokens go back to dropped items. Real tiktoken counts, and a final invariant: never over the window.

Persistent memory

Context that survives the session.

ContextManager adds durable storage around the assembler. One SQLite file, searchable instantly, deletable for real.

⚑

Namespaces, tags, provenance

Every entry knows who said it, when, and from which tool.

℗

Pinned + importance scoring

Assembly prefers fresh, high-importance, pinned entries.

↻

Full version history

Compact and update without losing what came before.

⚒

Tension detection

Inspection reports contradictions, staleness and duplicates instead of silently merging.

✕

Real deletion

The entry, its FTS index rows and its history all go. Gone for good.

python
from contextboss import ContextManager

mgr = ContextManager("context.db")
mgr.add("Staging deploys freeze on Fridays",
       tags=["deploy"], provenance="slack:#eng")
mgr.add("User is on the Pro plan since Oct 2",
       pinned=True, importance=2.0)

ctx = mgr.assemble("deploy freeze",
    system="You are a careful support engineer.",
    task="Why did the Friday deploy fail?",
    budget=8000)
print(ctx.render())  # never exceeds the window

mgr.compact(entry_id, target_tokens=100)
mgr.delete(entry_id)  # gone for good

Install it. Wire it into your agent. Done.

Three packages, one store. The engine imports as contextboss; the PyPI distribution is contextboss-core, so existing code keeps working.

bash
# the engine + CLI
pip install contextboss-core

contextboss                 # live demo: what got in, what got dropped, why
contextboss --budget 400    # squeeze it and watch the tiers fight
contextboss --show          # also print the final assembled prompt
python
from contextboss import ContextAssembler, MemoryStore, Retriever, ToolSpec

asm = ContextAssembler(budget=8000, output_reserve=1000)
asm.system("You are a careful support engineer.")
asm.task("Why are our exports returning 429?")

memory = MemoryStore()
memory.add("Customer upgraded to Pro on Oct 2", importance=2.0)
asm.load_memory(memory, query="429 export", k=10)

asm.tool(ToolSpec("get_usage", "Per-minute request counts",
                {"type": "object"}))

ctx = asm.assemble()
print(ctx.render())            # ready to send
print(ctx.total_tokens, "of", ctx.window)
for d in ctx.dropped():
    print(d.item_id, d.reason)   # every decision, explained

Tune the split with a BudgetPolicy: weights and caps per tier. The built-in MemoryStore and Retriever are small stand-ins: swap in a vector DB, keep the (item, score) shape, and feed scores in as priority=.

The MCP server exposes the whole context layer to any MCP-capable agent. Nine tools: context_add, context_search, context_get, context_update, context_delete, context_compact, context_assemble, context_inspect, context_stats.

bash · stdio (Claude Code / Desktop / Codex)
pip install contextboss-mcp
contextboss-mcp                                # store: ~/.contextboss/context.db
CONTEXTBOSS_DB=/path/to.db contextboss-mcp     # custom store
bash · streamable HTTP (Claude Web / ChatGPT connectors)
contextboss-mcp serve --http                   # optional bearer auth
The server stores its own context entries. It never reads or modifies the client's conversation history.

One command merges the MCP server, a SessionStart hook injecting your most relevant stored context, and PreCompact/Stop hooks storing session snapshots into ~/.claude/settings.json.

bash
pip install contextboss-mcp
contextboss-mcp install claude-code          # idempotent, preserves existing settings
contextboss-mcp install claude-code --print  # preview the merge without writing

Or register the server by hand:

bash
claude mcp add contextboss -- contextboss-mcp
Snapshots and injected context are ContextBoss entries. Your conversation history stays provider-owned: never read into the store, never modified.

Appends the server to ~/.codex/config.toml and adds a marked ContextBoss block to your project's AGENTS.md so the agent knows when to store and recall context.

bash
pip install contextboss-mcp
cd your-project
contextboss-mcp install codex            # idempotent, preserves existing content
contextboss-mcp install codex --print    # preview without writing
toml · what lands in ~/.codex/config.toml
[mcp_servers.contextboss]
command = "contextboss-mcp"

A FastAPI surface for anything that isn't an MCP client: CRUD, search, compact, inspect, assemble, stats, and sync endpoints under /v1.

bash
pip install contextboss-api
export CONTEXTBOSS_API_KEYS="my-secret-key"   # sha256-hashed at rest
contextboss-api                                 # http://127.0.0.1:8787
bash · example calls
curl -X POST http://127.0.0.1:8787/v1/contexts \
  -H "Authorization: Bearer my-secret-key" \
  -H "Content-Type: application/json" \
  -d '{"text": "Staging deploys freeze on Fridays", "tags": ["deploy"]}'

curl "http://127.0.0.1:8787/v1/contexts/search?q=deploy" \
  -H "Authorization: Bearer my-secret-key"
Bearer keys are whitespace-stripped and sha256-hashed, compared with secrets.compare_digest. The whole store is one SQLite file; back it up or sync it via /v1/sync/*.

A Next.js dashboard over the REST API: overview stats, entry search and filters, version history, tension reports, one-click compaction, and an assemble playground.

Open the dashboard, point it at your API, and watch entries arrive from every connected agent in real time.
